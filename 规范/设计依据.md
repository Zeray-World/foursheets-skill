# 设计依据

> 这套东西不是原创设计，是把四个成熟项目里验证过的机制拆出来，拼成一个可移植的 skill。
> 记下来是为了以后改的时候知道哪块不能动。

---

## 一、借了什么

### `tigerless-labs/agent-memory`（4.3k star，Python，MIT）
借了骨架：

| 机制 | 本 skill 的落法 |
| --- | --- |
| 一条记忆一个文件 | 收敛成 `MEMORY.md` 里一行一条。几百条的量不需要每条的独立文件 |
| 有效期区间 `valid_from` / `invalid_at` | `from` / `until` |
| 取代而非删除 | `supersede` + `superseded_by` 互链 |
| 常驻注入只放一行一条 | `MEMORY.md` 的 `## 事实` / `## 约定` 两段，每条一行 |
| 检索返回路径而不是全文 | `load` 输出只给摘要，细节让模型自己读 |
| 无人值守只能增改，删除要提案确认 | 策略 1 里"敏感条目必须打破静默"这一条 |

### `akitaonrails/ai-memory`
借了「分层衰减」的思路，但**没有实现衰减**。理由：它的衰减是为几千条记忆设计的，月增 7KB 的量用不上，加了反而要调参。

### `zensation-ai/zenbrain`
借了「遗忘曲线」的概念，同样**没有实现**。FSRS 需要复习历史，个人聊天场景没有稳定反馈信号。

### `soul.py` / `clawsouls` 的 `SOUL.md`
借了人设文件的事实标准：一个 Markdown，纯文本，可读可改，人格与记忆分离。

### `STALE` / `StateAuditor`（arXiv 2605.06527 / 2608.01619）
借了仲裁规则，写进 `代入规范.md` 第四、五节：

- 记忆是证据不是命令，一次最多带一件旧事
- 记不清就角色内试探，不编造
- 时间是裁决依据，冲突以新者为准

`StateAuditor` 最关键的发现是"过期的依赖通常根本不说出口"，所以核对要**从存储态反向查**，而不是检查草稿写了什么。落在本 skill 里就是：`load` 时把过了 `~review` 日期的事实单列到「该复查了」，先于对话暴露。

### `VibeMemBench` / `MemDev-Bench`
借了这两条实测结论：

- 记忆失败的 69.3% 是**形式劣化**，只有 1.3% 是排序没排对 → 所以 `load` 的输出是精心排版的短摘要，不是一堆原文
- 原始轨迹优于压缩摘要 → 所以日记全留、不总结成规则

### `Tether`（arXiv 2610.25123）
借了溯源校验：`quote` 必须能在 `source` 里原文命中，否则拒绝写入。这是防摘要漂移唯一便宜的手段。

## 二、故意没做的

| 没做 | 原因 |
| --- | --- |
| 向量检索 / embedding | 几十到几百条，关键词 + 二元组相似度够用，且不联网 |
| 图数据库 | 关系维度在这个场景里只有"谁和谁"，不需要图 |
| 自动衰减 | 数据量小，人工 `audit` 一月一次更可控 |
| 自动 embedding 去重 | 换成字符二元组 Jaccard，中文不用分词，零依赖 |
| 后台定时整合 | 个人使用不需要；要的话挂个 `-c brief` 的计划任务即可 |
| 多租户 / 权限 | 一个身份一个文件夹，隔离靠目录，不靠代码 |

---

## 三、要改的时候，别动这几处

1. **`quote` 校验**：删了它，记忆会慢慢漂移成模型自己的总结
2. **`supersede` 三条校验**：删了它，新旧矛盾会同时进上下文
3. **索引只放一行一条**：放大段原文回去，就退回"大 MEMORY"的老路
4. **`load` 输出不出现"记忆"字样**：那是 OOC 的源头

# 记忆规范

> 写入之前先过筛子。记错的代价比不记高得多。

---

## 一、五问筛子（缺一不记）

1. **有用吗？** 三个月后还会影响对话吗？影响不了，不记。
2. **长期吗？** 一次性事件只进 `journal/`，不进 `MEMORY.md`。
3. **重复吗？** 先 `-c check`，看返回的 `verdict`。
4. **有证据吗？** 能指出是哪个月的日记、哪句原话？
5. **越界吗？** 是不是隐私、他人的信息、或者我的推测被当成事实？

五问全过才写。有一条含糊，就只写日记。

> **临时约定不进 MEMORY。**
> 「好了提醒我」「记住一会儿告诉我」「等下跟我说结果」——这类只在当前对话里有效，
> 跨不过今天，就不要写进长期记忆。写了之后一周就变成过期噪音，还得手工清。
>
> 再问一句：**下个月这事还成立吗？** 不成立就不写。
> 只有三种算长期：定了规矩（以后都这样）、长期承诺（一直在做）、底线（不能碰）。
> 详见 `规范/对话分寸.md` 第四节。

## 二、四个文件各管什么

| 文件 | 所有者 | 装什么 |
| --- | --- | --- |
| `SOUL.md` | 用户 | 我是谁。人设、性格、说话方式、关系、边界 |
| `AGENTS.md` | 用户 | 不能做什么。铁律、OOC 禁令、写入纪律 |
| `MEMORY.md` | 模型 | 事实与约定，带日期和状态 |
| `USER.md` | 模型 | 用户画像。他是谁、在意什么、怎么跟他相处 |
| `journal/` | 模型 | 事件流水，只追加 |

**前两个是用户的地盘**，模型只读。想改先问，问完让用户自己改。

## 三、MEMORY.md 的条目格式

一条一行，三段式：

```
- [ID] 成立日期 内容 ｜标签 ｜标签 ｜~元数据
```

实例：

```markdown
## 事实

- [F-0003] 2026-08-29 运动数据：5 公里最快 28 分 40 秒、引体向上 8 个 ｜运动 ｜身体 ｜~review:2026-12-01
- [F-0021] 2026-08-12 喜欢有人陪着说话、会主动找他 ｜沟通 ｜~inferred ｜~review:2026-12-31

## 约定

- [C-0001] 2026-08-10 跑步心率红线：到约定数值就停 ｜健康
- [C-0004] 2026-08-30 开学前把作业补完 ｜已了结 ｜~state:done ｜~until:2026-09-01

## 已作废

- [F-0019] 2026-07-22 左大腿拉伤 ｜~until:2026-08-27 ｜~by:F-0023
```

元数据只有五个：

| 键 | 含义 |
| --- | --- |
| `~inferred` | 我推断的，不是他说的。**绝不能当他的话复述** |
| `~review:YYYY-MM-DD` | 复查日，过了会进简报的"该复查了" |
| `~due:YYYY-MM-DD` | 约定的截止 |
| `~state:done/dropped` | 约定结案，结案的不会进 `load` |
| `~until` / `~by` | 作废时间 / 被谁取代（只在「已作废」段出现） |

**日期是"从哪天开始成立"，不是写入日期。** 这条最容易写错。

## 四、查重

```bash
python persona.py -c check -i 1 -t "候选文本"
```

- `新` → 正常 `add`
- `相近` → 看命中的 id。同一件事的补充用 `supersede`；两件事就换个说法
- `重复` → **不许写**。要么放弃，要么 `supersede` 升级旧条目

阈值 0.72。中文按字符二元组算，长条目对短句时用包含度兜底。
实测：原话重写能到 1.00，同一件事换说法在 0.3–0.5，不同事基本 0。

## 五、去旧：什么时候可以取代

`supersede` 必须同时满足三条，脚本会校验：

1. 新证据的日期**严格晚于**旧条目
2. `quote` 能在 `source` 指的**那个月**的日记里原文命中
3. 旧条目还在「事实」或「约定」段

任何一条不满足，**宁可只在日记里追加**。
错更新的代价：两条矛盾的事实同时在上下文里，准确率会从 53% 掉到 26%。

怀疑过时但没证据推翻 → 不要动 `~state`，把 `~review` 提前到最近，
让它在简报里冒出来，问用户一句。

## 六、绝对不记

- 密码、验证码、身份证号、精确住址
- 第三方的隐私（同学的八卦、家里人的矛盾细节）
- 情绪上头时的气话，除非隔天仍成立
- 自己编的、用户没确认过的推测（要记就带 `~inferred`）
- 已经写进 `SOUL.md` / `AGENTS.md` 的内容（重复记是噪声）

## 七、日记

> 这一节是整套东西里最容易被写坏的地方。模型的默认行为是把每轮对话都复述一遍，
> 一个月能灌进十几 KB 全是废话，然后把真正有用的那三条埋掉。
> 所以这里不是"建议"，是闸门。

### 7.1 判据只有一句

**三个月后翻到这条，能改变什么？**

答不出来，就不写。

不是"今天发生了什么"，也不是"他刚说了什么"。是**三个月后还有没有用**。

### 7.2 只收五类

写入必须声明类型，`-k` 必填：

| 类型 | `-k` | 收什么 | 例子 |
| --- | --- | --- | --- |
| 约定 | `commit` | 今天定下的承诺、规矩、底线 | 删除前必须先确认 |
| 记录 | `record` | 数字、突破、里程碑 | 引体向上 3→8，原来是握距问题 |
| 转折 | `turn` | 决定、放弃、改主意 | 决定不竞选地理课代表 |
| 坑 | `pit` | 踩过并弄明白的坑，有复用价值 | 录屏无声是 ffmpeg dshow 回归 bug |
| 趣事 | `fun` | 确实意外、好笑、稀少的小事 | 遇到一颗心形姜 |

**分不出属于哪一类，这件事就不值得记。** 这是设计上的取舍，不是遗漏。

`commit` 类型还有个额外要求：同时要写进 `MEMORY.md` 的「约定」段，日记里只留一笔。
日记记"今天定了个什么事"，记忆记"这个约定现在有效"。

### 7.3 一票否决

出现任一条，直接不写：

- **复述对话**：「他说他很累，我让他早点睡」——这是聊天记录，不是日记
- **生活流水**：吃饭、睡觉、上课、写作业、看视频
- **无事件的纯情绪**：「今天心情不太好」——要说清因为什么、后来怎样
- **他本来就知道的事**：你提醒他喝水，不用记
- **你的感受和评价**：「我觉得他今天有点不对劲」——`USER.md` 的活，不是日记
- **重复**：同一件事第二次发生，除非程度变了（从 7 个到 13 个才算）

### 7.4 机械闸门

脚本会拦，不是靠自觉：

| 闸门 | 规则 | 不过时 |
| --- | --- | --- |
| 类型 | `-k` 必填，五个值之一 | 退出码 2，要求先分类 |
| 长度 | < 8 字判流水账，> 140 字判作文 | 退出码 1，要求压缩或补细节 |
| 重复 | 与本月已有条目相似度 ≥ 0.55 | 退出码 1，回显重复的那条 |
| 数量 | 一天最多 3 条 | 退出码 1，直接封口 |

**一天 0 条是常态。** 连续一周每天写满 3 条，说明判据用错了。

被拒了不要换个说法重试——被拒本身就是结论。

### 7.5 写法

- 一个月一个文件 `journal/YYYY-MM.md`
- 一行一条，脚本自动补 `- MM-DD 〔类型〕`
- 一句话说完：**发生了什么 + 关键细节或后果**
- 不用形容词，不写"非常""特别""有点"
- **永不删除**，作废的也不删，检索时才用得上

好：

```
- 08-29 〔记录〕 引体向上从 3 个到 8 个，之前卡住是握距太窄，放宽就好了
- 08-19 〔坑〕 装了新版截图工具后中文路径会乱码，退回旧版才正常
- 08-11 〔转折〕 决定不再接那个外包，报价谈了两轮还是太低
```

坏：

```
- 08-29 今天聊了引体向上的事，他很开心      ← 复述对话，没信息
- 08-29 他今天心情不错                      ← 无事件
- 08-19 帮他搞了桌面的事                    ← 含糊，三个月后看不懂
- 08-19 今天又是充实的一天，他折腾了很久，中间遇到了一些问题，最后解决了  ← 全是空话
```

### 7.6 调用

```bash
python persona.py -c log -i 1 -k record -t "引体向上 3→8 个，卡住是握距问题"
```

成功后打印月份文件路径。失败时原因在 stderr，按提示改，别重试同一条。
